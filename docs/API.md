# API GestSpeak

Базовый адрес: `http://127.0.0.1:8000`. Swagger: `/docs`, машинная схема: `/openapi.json`.

API сохраняет встречи в SQLite. Создание возвращает **202 Accepted** и `id`; обработка идёт в фоне. Запрашивайте `GET /api/meetings/{id}` до `status: ready` либо `status: error`. Поля `stage` и `progress` предназначены для интерфейса; `error` объясняет неуспешную обработку.

## Авторизация

По умолчанию локальный запуск работает без токена. Если задан `GESTSPEAK_API_TOKEN`, каждый запрос `/api/*` должен содержать `Authorization: Bearer …`. Храните секрет в окружении, не в репозитории. Примеры ниже предполагают локальный режим без токена; для защищённой среды добавьте `-H "Authorization: Bearer $GESTSPEAK_API_TOKEN"`.

## Создать встречу из текста

```bash
curl --fail http://127.0.0.1:8000/api/meetings/text \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{
  "title": "Проверка безопасности",
  "meeting_date": "2026-09-23",
  "consent": true,
  "language": "auto",
  "participants": ["Асхат", "Нурлан"],
  "transcript": "Асхат: Подготовить есеп по датчикам газа — ответственный Нурлан, срок до 15 октября.\nНурлан: Жақсы, сделаю."
}
JSON
```

Скопируйте `id` из ответа в `GESTSPEAK_MEETING_ID`, затем получите результат:

```bash
GESTSPEAK_MEETING_ID='id-из-ответа'
curl --fail "http://127.0.0.1:8000/api/meetings/$GESTSPEAK_MEETING_ID"
```

`engine: rules` означает ограниченный анализ локальными правилами без LLM: явные формулировки, обращения, отдельные уточнения сроков и выдержки из реплик. `engine: local-ai` означает ответ локальной модели, который всё равно требует проверки. Текст передавайте строками `Имя: реплика`. Поддерживаются до 60 000 символов и 50 участников.

## Загрузить запись

```bash
curl --fail http://127.0.0.1:8000/api/meetings/audio \
  -F 'file=@meeting.wav' \
  -F 'title=Производственное совещание' \
  -F 'meeting_date=2026-09-23' \
  -F 'consent=true' \
  -F 'language=auto' \
  -F 'speakers=3' \
  -F 'participants=Асхат,Нурлан,Айнур'
```

`language`: `auto`, `ru` или `kk`. `speakers` необязателен, от 1 до 30. `participants` — строка через запятую. Максимум 250 МБ и 2 часа. `consent=true` означает, что пользователь уведомил участников и имеет право обработать запись. API не даёт такого согласия за участников.

## Проверить поручение

```bash
GESTSPEAK_ACTION_ID='a1'
curl --fail -X PATCH \
  "http://127.0.0.1:8000/api/meetings/$GESTSPEAK_MEETING_ID/actions/$GESTSPEAK_ACTION_ID" \
  -H 'Content-Type: application/json' \
  --data '{"owner":"Нурлан","due_date":"2026-10-15","needs_review":false,"status":"in_progress"}'
```

Статусы: `open`, `in_progress`, `done`. Для подтверждения нужны ответственный и дата. Редактирование названия, ответственного или срока возвращает поручение к проверке, если тот же запрос явно не подтверждает обновлённый результат.

Поля поручения: `title`, `owner`, `deadline_text`, `due_date`, `due_start`, `topic`, `priority`, `status`, `evidence` (ID реплик), `quote`, `needs_review`, `review_reason`. Исходная формулировка срока сохраняется отдельно от календарной даты.

## Сопоставить голос и имя

```bash
curl --fail -X PATCH \
  "http://127.0.0.1:8000/api/meetings/$GESTSPEAK_MEETING_ID/speakers" \
  -H 'Content-Type: application/json' \
  --data '{"speaker":"SPEAKER_00","name":"Нурлан Сагатович"}'
```

Укажите существующий кластер из `segments`. Для повторного извлечения с подтверждёнными именами используйте `POST /api/meetings/{id}/reanalyze`. Успешный повторный анализ заменит список поручений и их статусы; он должен быть явным действием пользователя.

## Экспорт и напоминания

```bash
curl --fail \
  "http://127.0.0.1:8000/api/meetings/$GESTSPEAK_MEETING_ID/export/pdf" -o protocol.pdf
curl --fail \
  "http://127.0.0.1:8000/api/meetings/$GESTSPEAK_MEETING_ID/export/docx" -o protocol.docx
curl --fail \
  "http://127.0.0.1:8000/api/meetings/$GESTSPEAK_MEETING_ID/export/json" -o protocol.json
curl --fail http://127.0.0.1:8000/api/reminders
```

Напоминания используют календарную дату **Asia/Almaty**, включают незавершённые поручения со сроком в ближайшие три дня и просроченные. `draft` отличает ещё не проверенное поручение. Внешняя рассылка не выполняется.

Дополнительно: `GET /api/meetings/{id}/audio` — исходная запись, `GET /api/meetings/{id}/audit` — типы событий и время, `DELETE /api/meetings/{id}` — удалить встречу и аудио. `POST /api/demo` восстанавливает размеченный демонстрационный пример, включая исходные статусы.

## Ответы об ошибках

| Код | Причина |
|---|---|
| 400 | Нет уведомления участников, пустой файл или нет транскрипта для повтора |
| 401 | Нет корректного Bearer-токена |
| 403 | Недопустимый Origin для изменяющего запроса |
| 404 | Совещание, поручение, голос или формат не найден |
| 409 | Операция несовместима с текущей обработкой; экспорт ещё не готов |
| 413 | Файл больше 250 МБ |
| 415 | Неподдерживаемое расширение |
| 422 | Некорректные поля или подтверждение без ответственного и срока |
| 429 | Очередь заполнена; повторить позднее |
| 503 | Не подготовлены необходимые локальные модели |

Ошибки фонового задания отражаются в `status: error` объекта встречи, даже если запрос создания ранее вернул 202. Клиент должен проверять конечное состояние.
